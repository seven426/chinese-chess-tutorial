# 小小象棋家 2.0 — 设计文档

## 项目概述

面向零基础小学生的中国象棋网页闯关应用。在现有 1.0 版本基础上重构扩展，核心改进：增加 AI 黑方对手、补充防守类关卡、实时非法移动提示、修复胜利判定 bug。

## 目标用户

- 6-12 岁零基础小学生
- 需要亲切 UI、清晰引导、即时反馈
- 对挫败感敏感，AI 不能太强

## 系统架构

```
chinese-chess-tutorial/
├── index.html          ← 结构微调（新增非法提示气泡层、AI 思考条）
├── css/

├── js/

│   ├── ai-engine.js    ← 全新（Minimax + Alpha-Beta + 难度控制）

│   ├── validator.js    ← 全新（非法移动检测 + 原因映射 + 视觉辅助）
│   └── app.js          ← 重构（状态机 + AI 回合管理 + 胜负判定）
```

## 核心状态机

```
MENU → LEVEL_MAP → PLAYING → (VICTORY | DEFEAT) → LEVEL_MAP
```

`PLAYING` 内子状态：
- `USER_TURN` → 用户点击 → Validator 检查 → 合法则执行 → 检查目标 → 切 `AI_TURN`
- `AI_TURN` → AI 计算 → 执行黑方走法 → 检查红方将军/将死 → 切 `USER_TURN`

## 关卡系统

### 章节划分

| 章节 | 关卡 | 主题 | AI 强度 |
|------|------|------|---------|
| 第一章·棋子学堂 | 1-5 | 认识各子走法 | 无 AI |
| 第二章·攻其不备 | 6-13 | 进攻杀法 | depth=1-2，弱 |
| 第三章·守中带攻 | 14-20 | 防守解杀 + 反击 | depth=2-3，中 |
| 第四章·大师试炼 | 21-25 | 残局综合 | depth=3-4，强 |

### 目标类型

**原有（进攻）：**
- `move_to` — 移动到指定位置
- `capture` — 吃掉指定棋子
- `capture_all` — 吃掉所有目标棋子
- `check` — 将军
- `checkmate` — 将死

**新增（防守）：**
- `escape_check` — 成功解除将军状态
- `survive_n_moves` — N 步内不被将死
- `counter_capture` — 解杀同时反吃攻击子
- `defend_and_check` — 解杀后立刻反将

### 关卡数据结构

```js
{
  id: 14,
  name: "解杀逃将",
  chapter: 3,
  type: "defensive",        // tutorial | offensive | defensive
  objective: { type: "escape_check", withinMoves: 3 },
  aiDepth: 2,
  aiAggressive: true,       // 是否优先将军/吃子
  aiOpeningStyle: "aggressive", // 开局风格
  position: "4k4/9/9/9/9/9/9/9/4r4/4K4",
  hints: ["将帅被将军时必须解杀", "把将帅移出攻击线"],
  starSteps: [2, 3, 5],
  allowedPieces: null
}
```

### 三星评价

- **进攻关**：按步数评级（现有逻辑）
- **防守关**：在限定步数内解杀 + 未被吃子（未被吃子额外奖励）

## AI 引擎

### 算法

Minimax + Alpha-Beta 剪枝 + 深度控制。

### 评估函数

**动态棋子价值（关键设计）：**
- 开局（总子力 > 20）：炮 48 > 马 38
- 中局：炮 45 ≈ 马 42
- 残局（总子力 < 10）：炮 38 < 马 48

**其他因子：**
- 車 = 90（恒定最强）
- 将军奖励 +500
- 吃子奖励 +被吃子价值 × 0.5
- 随机扰动 ±5%

### 三级难度

| 级别 | 深度 | 行为特征 |
|------|------|----------|
| Level 1 | depth=1 | 仅评估当前吃子，不主动将军。教学关使用。 |
| Level 2 | depth=2 | 50% 最优解 + 50% 次优解，留破绽。 |
| Level 3 | depth=3-4 | 能看到连将，但评估函数削弱防守分，偏向进攻露漏洞。 |

### 约束

- 不故意避开用户杀招（不靠让着，靠自然降智）
- 不走自杀棋（不主动送将）
- 搜索期间显示"黑方思考中..."，最少 500ms

## 非法移动实时提示系统

### 触发时机

用户点击己方棋子后，再点击**非法目标位置**时触发。

### 提示映射

| 违规类型 | 提示文案 | 视觉辅助 |
|----------|----------|----------|
| 超出走法规则 | "【馬】要走'日'字形哦！" | 气泡 |
| 蹩马腿 | "马腿被挡住了！" | 高亮被挡位置 |
| 塞象眼 | "象眼被塞住了！" | 高亮象眼 |
| 将帅照面 | "将帅不能见面！" | 高亮两将之间直线 |
| 送将 | "不能送死哦！走完将被吃。" | 高亮对方攻击子 |
| 九宫限制 | "只能在九宫格内移动。" | 高亮九宫边界 |
| 兵未过河横走 | "小卒没过河，只能向前走。" | 高亮楚河汉界 |
| 关卡限制 | "这一关只能用指定棋子。" | 高亮可用棋子 |

### 防疲劳机制

- 同一错误连续触发 2 次后，缩短提示
- 同一错误连续 3 次，自动弹出该关卡第一条 hint

## 数据流与交互

### 走棋流程

1. 用户点击棋子 → Validator 检查权限 → 高亮合法落点
2. 用户点击目标 → Validator 判断
   - 合法：执行 → 检查关卡目标 → 达成则胜利 / 未达成则检查黑方状态 → 切 AI_TURN
   - 非法：显示提示气泡，停留 USER_TURN
3. AI_TURN：显示思考动画 → AI 计算 → 执行 → 检查红方将军/将死
   - 红方将死 → 失败
   - 红方将军 → 棋盘闪红边框
   - 正常 → 回 USER_TURN

### 动画时序

- 棋子移动：300ms
- AI 思考：最少 500ms
- 将军警告：红色脉冲边框 2s
- 提示气泡：3s 自动消失

## UI/UX 改进

- **AI 思考条**：棋盘上方浮动"黑方思考中..." + 旋转棋子图标
- **将军闪烁**：被将军时棋盘边框红色脉冲
- **走棋轨迹**：用户上一步金色高亮，AI 上一步灰色高亮
- **章节标识**：关卡地图上按章节分色（绿→橙→红→紫）

## 技术约束

- 纯前端（HTML/CSS/JS），无后端
- 数据持久化：localStorage
- 浏览器兼容：Chrome/Firefox/Safari 最新两版
- 响应式：支持 768px+ 平板和桌面

## 不在本次范围

- 联机对战
- 音效/语音（保留现有 Web Audio beep）
- PWA 离线功能
- 后端排行榜
